# Сравнение PWA, гибридного и нативного приложений

В лабораторной сравнивается PWA-версия списка задач, её Capacitor APK и нативный Android To-Do из лабораторной №6.

| Характеристика | PWA | Capacitor APK | Нативное Android-приложение |
| --- | --- | --- | --- |
| Интерфейс | HTML, CSS и JavaScript в браузере | Те же HTML, CSS и JavaScript внутри Android WebView | Kotlin и Jetpack Compose |
| Установка | Открывается по HTTPS/localhost; поддерживает установку из совместимого браузера | Устанавливается как Android APK | Устанавливается как Android APK |
| Офлайн-запуск | Service Worker кеширует оболочку; localStorage хранит список | Веб-ресурсы включены в APK; localStorage хранит список | Room хранит задачи в SQLite |
| Обновление интерфейса | При следующем посещении и обновлении кеша | После обновления APK или синхронизации веб-файлов с native-проектом | После выпуска новой версии приложения |
| Доступ к устройству | Только доступные браузеру Web API | Нативные функции через Capacitor-плагины | Прямые Android API и библиотеки |
| Переносимость кода | Один веб-проект для браузеров | Общая веб-часть плюс Android-оболочка | Android-специфичный проект |
| Подходящее применение | Лёгкий сервис, который удобно открывать ссылкой | Повторное использование веб-интерфейса с APK-дистрибуцией | Приложение с глубокой интеграцией и сложной платформенной логикой |

## Итог

PWA проще распространять и обновлять через веб, но установка и доступ к возможностям устройства зависят от браузера. Capacitor повторно использует веб-интерфейс и упаковывает его в Android-приложение, сохраняя доступ к нативным плагинам. Нативный вариант из лабораторной №6 использует Room и Compose, поэтому его локальная модель данных и интерфейс ориентированы непосредственно на Android.

В этой работе PWA и APK хранят список локально в localStorage. Данные не синхронизируются между браузером, Android-оболочкой и сервером.
